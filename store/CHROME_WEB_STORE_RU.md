# Публикация Leeway Guard в Chrome Web Store: пошаговая инструкция

Время на всю процедуру: 30–40 минут твоих действий, затем ожидание модерации (обычно несколько дней; так как расширение работает на всех сайтах, может уйти на углублённую проверку до 2–3 недель).

## Что загружать

| Что | Файл |
|---|---|
| Пакет расширения | `extension/dist/leeway-guard-0.1.3-chrome.zip` |
| Иконка магазина 128×128 | `store/assets/store-icon-128.png` |
| Скриншоты 1280×800 (до 5 штук) | `store/assets/screenshot-*.png` |
| Малая промо-плитка 440×280 | `store/assets/promo-small-440x280.png` |

Пересобрать пакет, если что-то менял: `node extension/scripts/pack.mjs` (из корня проекта). Внутри zip файл `manifest.json` должен лежать в корне архива, скрипт так и делает.

## Шаг 0. Что подготовить заранее

1. **Google-аккаунт с двухэтапной аутентификацией.** Без 2FA магазин не даст опубликовать расширение. Лучше завести отдельный аккаунт под проект (например, leeway.dev@gmail.com): его имя и почта будут видны пользователям.
2. **Публичная ссылка на политику конфиденциальности:** `https://leeway.icu/privacy.html` (заработает, когда сайт будет на VPS). Если сайт ещё не поднят, временные варианты:
   - **GitHub Pages** (лучший вариант): когда заведёшь GitHub, включи Pages для папки `/site`, и ссылка будет `https://<ник>.github.io/leeway-mcp/privacy.html`.
   - **Быстрый вариант без GitHub:** открой `site/privacy.html` в браузере, скопируй текст в Google Docs → «Файл → Поделиться → Опубликовать в интернете» → получишь публичную ссылку. Потом её можно заменить.
3. **Карта для оплаты $5** (разовый регистрационный взнос).

## Шаг 1. Регистрация разработчика

1. Открой **https://chrome.google.com/webstore/devconsole** и войди в Google-аккаунт.
2. Прими соглашение разработчика.
3. Оплати регистрационный взнос **$5**.
4. В разделе **Account** заполни:
   - **Publisher name**: `Leeway` (будет отображаться как автор);
   - **Contact email** и подтверди его по письму (без подтверждения кнопка публикации неактивна).

## Шаг 2. Загрузка пакета

1. В консоли нажми **+ New item** (или «Добавить новый элемент»).
2. Выбери файл `extension/dist/leeway-guard-0.1.3-chrome.zip`.
3. Если появилась ошибка про манифест, пришли мне её текст: исправлю и пересоберу.

## Шаг 4. Вкладка Privacy practices (самая важная для модерации)

**Single purpose** (единственное назначение), вставь:
> Leeway Guard checks wallet transaction and signature requests on websites before they reach the user's wallet, and shows what they would do (assets moved, approvals granted, known drainer patterns) so the user can reject dangerous ones.

**Permission justification**: для каждого разрешения скопируй обоснование из таблицы **Permission justifications** в `store/listing.md`:
- `storage`
- `contextMenus`
- `activeTab`
- **Host permissions** (`*.publicnode.com`, `api.gopluslabs.io`, `coins.llama.fi`, `api.coingecko.com`)
- **Content scripts on all sites**: обоснование из строки про `<all_urls>`. Это главное, на что смотрит модератор: объясняем, что запрос кошелька может прийти с любого сайта.

**Are you using remote code?** → **No, I am not using remote code**.

**Data usage** (какие данные расширение передаёт за пределы устройства). Отвечаем честно:
- Отметь **Financial and payment information**. Пояснение: адреса кошельков и детали проверяемой транзакции отправляются в публичные блокчейн-API (RPC, GoPlus, DefiLlama, CoinGecko) только для проверки. Нам ничего не передаётся, ничего не хранится.
- Остальные категории (личные данные, история браузера, местоположение и т. д.) не отмечай: расширение их не собирает.
- Поставь все три галочки внизу:
  - данные не продаются третьим лицам;
  - не используются для целей, не связанных с основной функцией;
  - не используются для оценки кредитоспособности.

**Privacy policy URL**: публичная ссылка из шага 0.

## Шаг 5. Вкладка Distribution

- **Visibility**: `Public`. Если хочешь сначала проверить на знакомых, выбери `Unlisted`: расширение будет доступно только по прямой ссылке.
- **Regions**: All regions.
- **Payments**: Free.

## Шаг 6. Отправка на модерацию

1. Нажми **Submit for review**.
2. Включи опцию **«Publish automatically after review»**, если хочешь, чтобы расширение вышло сразу после одобрения. Если хочешь выбрать дату запуска сам, отключи её: после одобрения появится кнопка ручной публикации (одобренная версия хранится 30 дней).
3. Статус смотри в консоли: `Pending review` → `Published` (или письмо с причиной отказа).

## Если пришёл отказ

Пришли мне текст письма, я исправлю. Частые причины:

| Причина | Что делаем |
|---|---|
| Слишком широкие разрешения | уточняем обоснование для content scripts; при необходимости сужаем |
| Нет или недоступна политика конфиденциальности | проверить, что ссылка открывается без входа в аккаунт |
| Описание не соответствует функциям | правим текст карточки |
| «Spam / keyword stuffing» | убираем лишние слова из описания |

## Как выпускать обновления

1. Я поднимаю версию в `extension/manifest.json` (например, 0.1.3) и пересобираю: `node extension/scripts/pack.mjs`.
2. В консоли: твоё расширение → вкладка **Package** → **Upload new package** → новый `...-chrome.zip`.
3. **Submit for review**. Обновления обычно проверяются быстрее первой публикации.
